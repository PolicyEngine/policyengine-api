`/v2/reports` records each user's report runs and reads a report as each user sees it. `POST /v2/reports` and `POST /v2/reports/{report_id}/runs` take an optional user credential (a bearer access token, the `PolicyEngine-Unauthenticated-User` header, or a server forwarding either); with one, the request is recorded in `user_report_run_associations` for the run it ended on, created or joined (each year's report run for a budget window), and the user's saved reports of the report take that time as `last_run_at`. Both answer the report with the run the simulation service named, which needn't be its newest, and name it as `run_id` when the report can't be read back (502) or the request can't be recorded (503); only admin users may force a re-run. `GET /v2/reports/{report_id}?run_id=` reads a chosen run; without `run_id`, a read answers the requesting user's newest recorded run, else the newest succeeded run that wasn't forced, else the newest run that wasn't forced. A report's label and description are the requesting user's saved report's, null without one. A saved detailed-save report's `last_run_at` is its owner's newest request, and a sign-in that merges a browser into an existing account moves the browser's run records with it.
