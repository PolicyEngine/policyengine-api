`/v2/reports` records each user's report runs and reads a report by run. `POST /v2/reports` and `POST /v2/reports/{report_id}/runs` take an optional user credential (a bearer access token, the `PolicyEngine-Unauthenticated-User` header, or a server forwarding either); with one, the request is recorded in `user_report_run_associations` for the run it ended on, created or joined, and the user's saved reports of the report take that time as `last_run_at`. Both answer the report with the run the simulation service named, which needn't be its newest, and `GET /v2/reports/{report_id}?run_id=` reads a chosen run. A saved detailed-save report's `last_run_at` is its owner's newest request, and a sign-in that merges a browser into an existing account moves the browser's run records with it.
