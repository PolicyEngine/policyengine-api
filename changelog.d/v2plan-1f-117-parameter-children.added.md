Catalog publication writes each catalog version's parameter tree into a new table, parameter_tree_children, derived from the version's stored parameters and parameter nodes: one row per node and parameter under its parent's path, with its label, its position among its siblings, its direct child counts, and whether a reform can change it. A bracket schedule is one node whose children are its brackets, labelled "Bracket 1", "Bracket 2" and so on, and labels take the form the app's v3 workspace shows, with a path without a stored label getting one made from the last part of its name. Publication writes the tree of each version it publishes, and of the installed version when an earlier release stored it without one, built from the installed packages' catalog; its evidence lists them. Other versions stored before this change keep having no tree.
