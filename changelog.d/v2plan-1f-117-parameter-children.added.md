Catalog publication writes each catalog version's parameter tree into a new table, parameter_tree_children, derived from the version's stored parameters and parameter nodes: one row per node and parameter under its parent's path, with its label, its position among its siblings, its direct child counts, and whether a reform can change it. A bracket schedule is one node whose children are its brackets, labelled "Bracket 1", "Bracket 2" and so on, and a path without a stored label gets one made from the last part of its name. On every run, publication also writes the tree of each stored version that has none, so versions published earlier get it from the next deploy; the evidence lists each version written.
