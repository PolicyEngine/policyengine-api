Dual-write no longer fails the request when a copy to v2 fails. With `DB_WRITE_POLICY` or `DB_WRITE_HOUSEHOLD` set to `dual_write`, a policy, saved-policy or household write that commits to Cloud SQL now returns its normal response even if the copy to Supabase fails, including when the v2 catalog cannot translate the policy. The failure is logged with its existing metric and failure category, saved-policy and household events stay pending, and the same response is returned as with `cloud_sql`. Previously such failures returned HTTP 503.
