The detailed-save database can share identical simulations, reports and runs. `simulations` and `reports` gain optional key columns (`key_version`, `definition_key`, and on reports `dataset_independent_key`), unique on the key and its version; `simulation_runs` and `report_runs` gain a `forced` marker, false by default; partial unique indexes allow one run that hasn't failed and isn't forced per simulation, year, catalog version and package versions, and per report and package versions outside budget windows; `budget_window_runs` records its .py version, with one window run per report and version set that hasn't failed and isn't recalculated; and the new `user_report_run_associations` table records each user's request for a report run, which the Public API's runtime role reads, inserts and deletes.
