Catalog publication reads regions from the Public API's checked-in reference files, one per country, instead of PolicyEngine.py's region registry. Each region takes its dataset from the certified data release and its filter from a scoping rule: a row filter on state_fips, congressional_district_geoid or the UK region column, or a weight_replacement filter naming the release's constituency or local-authority weight matrix and the region's ONS code. The UK now publishes 1,015 regions, with constituencies and local authorities by ONS code and Northern Ireland as country/northern_ireland; the national regions are "United States" and "United Kingdom". US places are listed in the reference file but left out of the catalog until they can run, and the publication evidence counts them. Before it publishes a catalog version that is not stored yet, the publication command reads the HDF5 metadata of the certified artifacts the filters use, from Hugging Face at their pinned revisions, and stops if a row filter's column is missing from its dataset or a weight matrix has no row for a region's code; the seed workflow's publication step receives the UK data read token as HUGGING_FACE_TOKEN for this. A catalog version that is already stored keeps the regions it was published with, so region file changes take effect in the next catalog version; republishing it logs the difference in region rows instead of failing, and every other table must still match.
