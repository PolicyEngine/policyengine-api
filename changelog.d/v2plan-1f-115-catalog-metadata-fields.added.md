Catalog format 2 stores the metadata the app's v3 workspace reads, taken only from PolicyEngine.py's public records: each model version's entities and basic inputs; each variable's input and hidden-input flags, module, the parameter path its adds or subtracts names, and its enum values' labels; each parameter's economy and household flags. Bracket schedules are stored as parameter nodes with their stored label. A generated revision adds the columns as nullable, so catalog versions published earlier keep them empty and are compared without them when republished. An opt-in parity test, run by the v2 integration check, compares every new field for the US and the UK with /{country}/metadata. UK constituencies and local authorities follow what the certified data release provides: with the weight matrices they keep the weight_replacement filter, and in a release without them that routes each region type to its own dataset they use a row filter on constituency_code_oa or la_code_oa with the ONS code, on that dataset; a release with neither stops publication.
